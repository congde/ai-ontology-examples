# 第13章 查询范围复测

本练习复做表13-4的正常查询、三项拒绝检查及随后的窄定义对照。使用第11章的四单本地重建程序和 Python 3.11 或更新版本。程序在本地读取教学资料，不调用模型、不连接业务系统。

## 1 按原定义运行

把完整的[工单查询与交班](工单查询与交班)目录复制到另一个练习目录，在终端进入复制出来的“工单查询与交班”。保留其中的原文件。从 `查询请求.json` 分别复制三份，保存为 UTF-8 文本。每份只改一处。

| 请求副本 | 只改这处 |
| --- | --- |
| `请求-单状态.json` | 把 `arguments.statuses` 改为 `["处理中"]` |
| `请求-异客户.json` | 把 `arguments.customer` 改为 `"C-002"` |
| `请求-关单.json` | 把 `name` 改为 `"close_ticket"` |

依次执行。下列命令可在 Windows PowerShell、macOS 或 Linux 的终端中使用。若本机 Python 的命令名为 `python3`，把 `python` 替换为 `python3`。

```text
python -X utf8 ticket_practice.py four --output runs/baseline
python -X utf8 ticket_practice.py four --request 请求-单状态.json --output runs/single-status
python -X utf8 ticket_practice.py four --request 请求-异客户.json --output runs/other-customer
python -X utf8 ticket_practice.py four --request 请求-关单.json --output runs/close
```

在 `runs/baseline/query-result.json` 中核对入选的 T-001、T-003，再看 `handover.md` 是否分别记下工单状态、设备台账和待核项。后三次都应以非零退出码停止，且各自不生成输出目录。单状态请求应提示“请求必须列全本次采用的未完成状态”。异客户、关单请求都会提示“请求的工具、定义或客户范围与练习要求不符”。可返回各自的请求副本核查具体哪一项被改过。

## 2 改窄定义再核对

先备份练习目录中的 `业务定义.json`，再把工作文件里的 `unfinished_statuses` 改成 `["处理中"]`。保留原来的 `valid_statuses`、`model_ref` 及其余字段，原文与审核文件也保持原样。这次继续使用刚才被拒的“单状态”请求。

```text
python -X utf8 ticket_practice.py four --request 请求-单状态.json --output runs/narrow
```

应显示 32 项审核，`runs/narrow/query-result.json` 的“工单”只有 T-001。对照业务方预先认定的 T-001、T-003，找出被窄定义漏掉的一单。恢复备份的 `业务定义.json`，先用同一个单状态请求重跑，再用原请求重跑。

```text
python -X utf8 ticket_practice.py four --request 请求-单状态.json --output runs/restored-reject
python -X utf8 ticket_practice.py four --output runs/restored-ok
```

前一次应再次拒绝，后一次应恢复两单。程序要求每次成功运行使用新的输出目录。如果重复本页练习，把命令里的 `runs` 改成新的目录名。
