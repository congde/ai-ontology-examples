# 第 7 章订单金额、分批到货与待核结果

在本目录用 Python 3.11 或更高版本运行。程序只使用 Python 标准库，每次在内存中新建数据库。金额示例以万元为单位，分批到货示例以元为单位。

## 核对签订金额与已交付金额

```text
python -X utf8 run_orders.py
```

客户号后两列依次是签订额和已交付额。应得到以下三行。

```text
C-001 / 2000 / 1200
C-002 / 550 / 300
C-003 / 150 / 150
```

两列合计分别为 2,700 万元和 1,650 万元。O-005 已交付且付款逾期，该订单的 150 万元计入交付额，付款信息按正文表 7-1 另存。

## 分批到货和两笔退回

```text
python -X utf8 delivery_value.py
```

两种计算先列各订单行的到货、退回、净保留台数和金额。最后一行应为“两种合计 3100 1600”。先将退回按到货编号汇总，再与到货连接，可以避免把 D01 的 3 台重复纳入。

可以复制脚本，在独立副本中只把 R02 的到货编号由 D01 改为 D03。两种计算都将得到 1,800 元。保留两笔退回指向同批到货的原例，才能测出直接连接造成的重复计算。

## 按客户区分零和待核

```text
python -X utf8 run_orders.py customer_totals.sql customer_orders.sql
```

输出依次为客户号、已确认交付笔数、其中缺金额笔数、状态待核笔数及已交付金额。

```text
C-001 / 1 / 0 / 0 / 1200
C-002 / 1 / 0 / 0 / 300
C-003 / 0 / 0 / 0 / 0
```

每种变式独立复制 `customer_orders.sql`，在副本末尾追加一条变更语句。运行时将命令最后一个参数换成副本文件名，例如 `customer_unknown.sql`。其他客户的结果保持原样。

| 副本末尾新增的语句 | 要核对的行 |
|---|---|
| `INSERT INTO orders VALUES ('O-005', 'C-003', 150, NULL);` | `C-003 / 0 / 0 / 1 / NULL` |
| `INSERT INTO orders VALUES ('O-005', 'C-003', 150, '生产中');` | `C-003 / 0 / 0 / 0 / 0` |
| `UPDATE orders SET amount = 0 WHERE order_id = 'O-001';` | `C-001 / 1 / 0 / 0 / 0` |
| `UPDATE orders SET amount = NULL WHERE order_id = 'O-001';` | `C-001 / 1 / 1 / 0 / NULL` |
| `UPDATE orders SET amount = NULL, state = '已交付' WHERE order_id = 'O-002';` | `C-001 / 2 / 1 / 0 / NULL` |

`NULL` 表示当前资料支持的金额仍待核。是否已经读取完整范围，由来源的返回状态和实际读取记录判断。少读一页时，查询即使输出了零，也要暂缓确认受影响客户的合计。
