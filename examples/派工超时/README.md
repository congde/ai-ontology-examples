# 派工超时后的反查与重发

对应第 12.2.1 节。在新的可写目录放入 [dispatch_demo.py](dispatch_demo.py) 和 [dispatch_verify.py](dispatch_verify.py)，使用 Python 3.11 或更新版本运行。程序只用标准库，各对照都从新建内存库开始。

```text
python -X utf8 dispatch_demo.py
python -X utf8 dispatch_verify.py
```

第一个程序让 duty-a 提交 R-01，为工单 WO-A 在 Q-A 队列建待办。数据库写入后，程序故意让响应超时。duty-b 只能从获准的交班查询按原发起人和原请求号查回待办 1。

第二个程序比较原待办号、重发取回的待办号和库内总数。

| 只改一项的对照 | 结果 |
|---|---|
| duty-a 用 R-01 和原参数重发 | (1, 1, 1) |
| duty-a 换成 R-02 并提交同一工单及队列 | (1, 2, 2) |
| duty-b 用 R-01 提交同一工单及队列 | (1, 2, 2) |
| duty-a 保留 R-01，改工单或队列 | 提示“原请求的参数不一致”，库内仍一项 |
| duty-b 只在自己名下找 R-01，再从获准入口按 duty-a 的原申请查 | 先无结果，再查到待办 1 |
| duty-c 查原请求，或 duty-b 从交班入口查 duty-a 的 R-02 | 均未获反查授权 |

待办表用调用者与请求编号作为唯一标识，再核对工单和队列。提交函数用于对照库内变化，未接入企业授权、派工队列规则或远程去重期限。若业务要求工单在同一队列只能有一项有效待办，还需在目标服务写入时落实并发限制，再用换账号和换编号的用例核实。实际值班查到原待办后，按原申请补记即可。
